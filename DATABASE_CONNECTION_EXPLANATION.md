# Подробное объяснение подключения к базе данных

## Как происходит подключение к БД в вашем приложении

### 1. Создание пула соединений (Connection Pool)

В файле `backend/src/config/database.js` создается **пул соединений** (connection pool):

```javascript
const pool = new pg.Pool({
  connectionString: process.env.DATABASE_URL,
  max: 10,  // МАКСИМАЛЬНОЕ количество одновременных соединений
  ssl: process.env.DB_SSL === 'true' ? { rejectUnauthorized: false } : false
});
```

**Что такое пул соединений?**
- Это набор готовых соединений с базой данных, которые переиспользуются
- Вместо создания нового соединения для каждого запроса, приложение берет соединение из пула, использует его, и возвращает обратно
- Это намного быстрее и эффективнее, чем создавать новое соединение каждый раз

### 2. Как работает пул в вашем приложении

**Максимальное количество одновременных пользователей: 10**

Параметр `max: 10` означает:
- Одновременно может быть **максимум 10 активных соединений** с базой данных
- Если 11-й пользователь пытается выполнить запрос, он будет ждать, пока одно из соединений освободится
- После завершения запроса соединение возвращается в пул и может быть использовано другим запросом

**Пример работы:**
1. Пользователь 1 делает запрос → берет соединение из пула (соединений свободно: 9)
2. Пользователь 2 делает запрос → берет соединение из пула (соединений свободно: 8)
3. ...
4. Пользователь 10 делает запрос → берет соединение из пула (соединений свободно: 0)
5. Пользователь 11 делает запрос → **ждет**, пока освободится одно из соединений
6. Пользователь 1 завершил запрос → возвращает соединение в пул → Пользователь 11 может использовать это соединение

### 3. Как используется пул в коде

В файле `backend/src/services/databaseService.js`:

```javascript
export async function query(sql, params = []) {
  const client = await pool.connect();  // Берем соединение из пула
  try {
    const result = await client.query(sql, params);
    return result;
  } finally {
    client.release();  // ВАЖНО: возвращаем соединение в пул
  }
}
```

**Важные моменты:**
- `pool.connect()` - берет соединение из пула (или ждет, если все заняты)
- `client.release()` - **обязательно** возвращает соединение в пул
- Блок `finally` гарантирует, что соединение будет возвращено даже при ошибке

### 4. Параллельность выполнения транзакций

**Да, ваше приложение обрабатывает параллельность транзакций!**

#### Как это работает:

1. **PostgreSQL обрабатывает параллельные транзакции автоматически**
   - Каждое соединение из пула может выполнять свою транзакцию независимо
   - PostgreSQL использует механизм MVCC (Multi-Version Concurrency Control) для изоляции транзакций

2. **Уровни изоляции транзакций**
   - По умолчанию PostgreSQL использует уровень `READ COMMITTED`
   - Это означает, что каждая транзакция видит только зафиксированные изменения других транзакций

3. **Пример параллельной работы:**

```
Время    Пользователь 1                    Пользователь 2
----------------------------------------------------------
T1       BEGIN TRANSACTION
T2       SELECT * FROM product             BEGIN TRANSACTION
T3       UPDATE product SET price=100      SELECT * FROM product (видит старую цену)
T4       COMMIT                            UPDATE product SET price=200
T5                                          COMMIT (может получить ошибку, если конфликт)
```

4. **Ваши хранимые процедуры**
   - Процедуры в PostgreSQL выполняются в транзакциях
   - Каждый вызов процедуры - это отдельная транзакция
   - Процедуры могут выполняться параллельно для разных пользователей

**Пример из вашего кода:**
```sql
CREATE OR REPLACE PROCEDURE create_order(...)
-- Эта процедура выполняется в своей транзакции
-- Если два пользователя одновременно создают заказы, 
-- они выполняются параллельно без конфликтов
```

### 5. Что происходит при превышении лимита соединений?

Если все 10 соединений заняты:
- Новые запросы **ждут** в очереди
- Express.js обрабатывает HTTP-запросы асинхронно, поэтому сервер не блокируется
- Как только одно соединение освобождается, следующий запрос его использует

**Рекомендации:**
- Для небольшого приложения (до 100 одновременных пользователей) 10 соединений обычно достаточно
- Если нужно больше, можно увеличить `max` до 20-50 (но не слишком много, т.к. каждое соединение потребляет ресурсы БД)
- Для очень больших нагрузок используют несколько серверов приложений или более сложные архитектуры

### 6. Безопасность и ошибки

В вашем коде есть обработчик ошибок пула:

```javascript
pool.on('error', (err) => {
  console.error('Unexpected PG pool error', err);
});
```

Это обрабатывает ошибки на уровне пула (например, разрыв соединения с БД).

### 7. Итоговая схема работы

```
HTTP Запрос → Express Router → Controller → databaseService.query()
                                                      ↓
                                              pool.connect() [берет соединение]
                                                      ↓
                                              client.query() [выполняет SQL]
                                                      ↓
                                              client.release() [возвращает в пул]
                                                      ↓
                                              Ответ клиенту
```

**Все это происходит параллельно для разных пользователей!**
